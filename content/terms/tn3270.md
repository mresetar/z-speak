3270 terminals were SNA devices. The applications they talk to — TSO, CICS, IMS, session managers — are still SNA applications that expect a terminal identified by a logical unit name. TN3270 is the bridge: the 3270 data stream travels inside a Telnet connection, and a server on z/OS turns each incoming TCP connection into an SNA session with **VTAM**.

That server is the **TN3270E Telnet server**, part of Communications Server and run as its own started task. Its configuration maps clients to LU names — from a pool, or specifically by IP address, host name or user — and decides what a connecting user sees first, typically a welcome screen from which an application is chosen. The `E` stands for the enhanced protocol, which adds printer sessions and lets a client request a particular LU.

The client is an emulator: IBM Personal Communications, the open-source x3270 family, or any of the commercial and browser-based products. All it needs is a host name and port.

Port 23 is unencrypted, and a 3270 logon sends the user ID and password in the clear, so production access should use TLS — conventionally on port 992 — implemented with AT-TLS. An emulator that connects but shows a blank screen or disconnects at once usually has a TLS or LU-mapping mismatch, not a network problem.
